# Introduction to Lex/Flex Programming

A Lex (or Flex) program is a tool used to generate lexical analyzers (scanners). It takes a set of regular expressions you define, matches them against an input text, and executes C code whenever a match is found.

## 🏗️ The Three-Part Structure

A Lex (`.l`) file strictly follows a three-part structure, separated by double percent signs (`%%`).

```lex
/* 1. Definitions Section */
%{
  /* C code goes here */
%}
  /* Lex macros go here */
%%

/* 2. Rules Section */
  /* pattern { action } */
%%

/* 3. User Subroutines Section */
  /* C functions (main, etc.) go here */
Here is a detailed breakdown of exactly what you need to write in each section.

📖 Section Breakdown
1. The Definitions Section
This section sets up your environment. It contains two distinct types of definitions: C declarations and Lex macros.

C Declarations: Enclosed within %{ and %}. Anything written here is copied verbatim to the generated C file. You should put your #include statements, global variables, and function prototypes here.

Lex Macros (Regular Expression Definitions): Written below the %}. You can assign names to complex regular expressions to make your rules cleaner and easier to read.

What to write here:

Code snippet
%{
#include <stdio.h>
int word_count = 0;
int num_count = 0;
%}

/* Lex Macros */
DIGIT    [0-9]
LETTER   [a-zA-Z]
WORD     {LETTER}+
NUMBER   {DIGIT}+
2. The Rules Section
This is the core of your Lex program. It starts after the first %%. Here, you define what patterns you are looking for in the input text and what C code to run when that pattern is found.

Format: pattern { action }

Important Built-in Variables:

yytext: A string containing the exact text that was matched.

yyleng: The length of the matched text.

What to write here:

Code snippet
%%
{WORD}      { 
              printf("Found a word: %s\n", yytext); 
              word_count++; 
            }

{NUMBER}    { 
              printf("Found a number: %s\n", yytext); 
              num_count++; 
            }

\n          { /* Ignore newlines */ }

.           { /* Catch-all for any other character to prevent printing it */ }
%%
3. The User Subroutines Section
This section starts after the second %%. Any C code written here is appended to the bottom of the generated C file.

At a minimum, you usually need a main() function to drive the program and a yywrap() function.

yylex(): This is the core function generated by Lex. You call it to start scanning the input.

yywrap(): Lex calls this function when it reaches the end of the input file (EOF). If it returns 1, Lex stops. If it returns 0, Lex expects you to point it to a new file to continue scanning.

What to write here:

Code snippet
int main() {
    printf("Enter text (Ctrl+D to end):\n");
    yylex(); // Start the lexical analysis
    
    printf("\nTotal Words: %d\n", word_count);
    printf("Total Numbers: %d\n", num_count);
    
    return 0;
}

int yywrap() {
    return 1; // Tell Lex to stop at EOF
}
🚀 Compiling and Running (Windows using win_flex)
To compile and run your Lex program on Windows using win_flex, follow these commands in your terminal or command prompt:

1. Generate the C source file:

Bash
win_flex -o lex.yy.c your_file.l
Note: The -o flag tells the compiler to create a specific .c file based on your .l file. In this example, it creates lex.yy.c.

2. Compile the generated C file into an executable:

Bash
gcc lex.yy.c -o your_program.exe
Note: In this step, the GCC compiler takes the C file created by win_flex and compiles it into an executable (.exe) file.

3. Run the executable:

Bash
.\your_program.exe
